دليل تعديل محتوى البورتفوليو

ابدأ من هنا

الدليل ده خاص بالسورس المحدّث المرفق مع الموقع. معظم المحتوى قابل للتعديل من ملف واحد:

src/content.json

التصميم، الألوان، الخطوط، المسافات، وطريقة عرض الأقسام منفصلة عن البيانات. مش محتاج تغيّرها علشان تعدّل مشروع أو تضيف خبرة أو شهادة.

مهم: عدّل content.json الموجود داخل السورس، مش ملف الـHTML المستقل. الـHTML نسخة مصدّرة؛ لازم تعيد بناءها وتصديرها بعد تغيير البيانات. تعديل JSON على جهازك لا يغيّر الموقع المنشور تلقائيًا.

تشغيل الموقع وقت التعديل

افتح مجلد السورس في VS Code، ثم افتح Terminal داخل نفس المجلد:

npm install
npm run dev

افتح الرابط اللي يظهر في Terminal. احفظ تعديلاتك في src/content.json؛ المعاينة المحلية تتحدّث تلقائيًا. لو ظهر خطأ أحمر، غالبًا فيه مشكلة في صيغة JSON؛ راجع قسم الأخطاء في آخر الدليل.

2. قواعد JSON الأساسية

  • لا تغيّر أسماء المفاتيح؛ غيّر القيم فقط، إلا عند إضافة عنصر جديد بالطريقة الموضحة.
  • استخدم علامات التنصيص العادية "، وليس علامات التنصيص المزخرفة.
  • النصوص بين علامات تنصيص، مثل "AI Engineer".
  • القوائم بين []، والعنصر الواحد بين {}.
  • افصل العناصر بفاصلة، لكن لا تضع فاصلة بعد آخر عنصر في القائمة أو الكائن.
  • اكتب true وfalse بدون علامات تنصيص. "false" نص، ولن يخفي العنصر.
  • JSON لا يقبل التعليقات مثل // comment.
  • لو محتاج سطرًا جديدًا داخل نص، استخدم \n بدل كسر السطر داخل علامات التنصيص. عرضه في الصفحة قد يظل متصلًا حسب مكانه.
  • لو محتاج علامة تنصيص داخل النص، اكتبها هكذا: \".
  • الأجزاء الموجودة في الأمثلة التالية مقاطع توضيحية، وليست بديلًا لملف content.json بالكامل.

قبل التعديل الكبير، خُد نسخة احتياطية من الملف.

3. البيانات الشخصية والبداية والتواصل — config

الاسم والنبذة والصورة

المفتاح داخل config بيعمل إيه؟
firstname الاسم الأول؛ يدخل في العلامة أعلى الموقع والاسم المعروض.
lastname اسم العائلة؛ يتجمع مع الاسم الأول تلقائيًا.
primaryRole التخصص المختصر أسفل العلامة وفي بطاقة Background، مثل AI Engineer.
loc المكان داخل البطاقة، ويظهر أيضًا بعد عبارة Based in.
portrait مسار صورتك المحلية، مثل /images/eyad-portrait.webp.
aboutp1 أول فقرة في نبذة Background.
aboutp2 ثاني فقرة في النبذة.
aboutp3 فقرة ثالثة اختيارية؛ اتركها "" لو مش محتاجها.
profileEducation اسم المؤهل المختصر داخل البطاقة.
graduationYear سنة التخرج الظاهرة بجوار المؤهل؛ نص مثل "2026".
countryCode اختصار البلد بجوار المكان، مثل EG.
profileStatus العبارة الصغيرة أسفل البطاقة، مثل OPEN TO WHAT’S NEXT.

اكتب فقرات النبذة كنص عادي، بدون وسوم HTML مثل <strong>. الفقرة الفارغة لا تظهر.

عنوان البداية ووصفها

المفتاح بيعمل إيه؟
heroRole الشارة الصغيرة أعلى العنوان الرئيسي.
heroTitle السطر الأول من العنوان، حاليًا Engineering.
heroAccent السطر الملوّن من العنوان، حاليًا intelligence..
badge عبارة إتاحة الفرص تحت أزرار البداية.
heroDescription.lead الجملة الأولى في الوصف.
heroDescription.beforeFocus النص قبل الجزء المميز بالخط الأوضح.
heroDescription.focus الجزء المميز بالخط الأوضح.
heroDescription.afterFocus تكملة الوصف بعده.

مثال على شكل الكائن الفرعي داخل config:

"heroDescription": {
  "lead": "I turn complex data into intelligent systems.",
  "beforeFocus": "Building across",
  "focus": "LLMs, computer vision, and production AI",
  "afterFocus": "— from the first experiment to the deployed product."
}

حافظ على طول معقول للعناوين علشان التوازن البصري يفضل زي ما هو.

الأرقام والمؤهل في البداية

المفتاح بيعمل إيه؟
stat1n عدد المستودعات كنص، مثل "40+". علامة + تُنسّق تلقائيًا.
stat1l وصف الرقم الأول، مثل PUBLIC REPOSITORIES.
stat2l وصف عداد المشاريع، مثل AI SYSTEMS & PROJECTS.
stat3n سنوات التعلم والبناء، مثل "3+". ليست سنوات خبرة وظيفية بالضرورة.
stat3l وصف الرقم الثالث.
heroEducation.degree اسم المؤهل المختصر بجانب الأرقام، مثل CS & AI.
heroEducation.school اختصار الجامعة، مثل EELU.
heroEducation.classOf سنة الدفعة كنص، مثل "2026".

عدد المشاريع في البداية يُحسب تلقائيًا من المشاريع الظاهرة. ما تحتاجش تكتبه بنفسك. المفتاح القديم stat2n مش هو اللي بيتحكم فيه.

البريد وروابط الحسابات

المفتاح الاستخدام
contact-email البريد الفعلي في قسم Contact وزر النسخ وروابط mailto:. ده المفتاح المهم للبريد.
github رابط حساب GitHub.
linkedin رابط LinkedIn.
upwork رابط حساب Upwork.
freelancer رابط Freelancer.
mostaqel رابط Mostaql؛ لاحظ إن اسم المفتاح مكتوب mostaqel.
khamsat رابط Khamsat.

اكتب رابطًا كاملًا يبدأ بـhttps://. لو حذفت قيمة رابط عمل حر وخليتها ""، رابطه يختفي من قسم Contact. احتفظ بروابط GitHub وLinkedIn صالحة لأن لها أماكن أساسية في الواجهة.

خانات قديمة داخل config لا تتحكم في الواجهة الحالية

المفاتيح دي محفوظة من بيانات الموقع السابق: email، herodesc، edu، roles، prog، portfolio، curr، theme، purl، وstat2n.

  • تغيير email لا يغيّر بريد Contact؛ استخدم contact-email.
  • تغيير herodesc لا يغيّر وصف البداية؛ استخدم heroDescription.
  • تغيير edu لا يغيّر المؤهل المعروض؛ استخدم profileEducation أو heroEducation أو قائمة edu حسب المكان المطلوب.
  • تغيير theme لا يحوّل الموقع إلى تصميم فاتح؛ الهوية الداكنة موجودة في CSS.
  • تغيير purl لا يغيّر رابط النشر أو الدومين.

4. الخبرات — exp

exp قائمة؛ كل كائن فيها يمثل خبرة واحدة. ترتيب العناصر في JSON هو ترتيب الخط الزمني. الأفضل وضع الأحدث أولًا.

الخانة معناها
id معرّف فريد ثابت، مثل exp-2026-01. لا تكرر نفس المعرّف.
title المسمى الوظيفي أو اسم التدريب.
org اسم الشركة أو الجهة.
date الفترة كنص حر، مثل 2026 — Present.
desc وصف مختصر لما عملته.
current true لإظهار شارة CURRENT على الخبرة الحالية.
visible true للعرض، وfalse للإخفاء بدون حذف البيانات.
icon حقل قديم اختياري؛ الإيموجي فيه لا يتحكم في أيقونة الخط الزمني الحالية.

إضافة خبرة

انسخ كائن خبرة موجود، ضعه داخل قائمة exp، غيّر الـid وباقي البيانات. مثال:

{
  "id": "exp-new-role",
  "title": "AI Engineer",
  "org": "Your Company",
  "date": "2026 — Present",
  "desc": "Describe your responsibilities and actual work here.",
  "current": true,
  "visible": true
}

لو الخبرة السابقة انتهت، غيّر current فيها إلى false وحدّث تاريخها. الشارة لا تتحرك تلقائيًا بناءً على التاريخ.

5. التعليم — edu

الخانات المستخدمة هي id، title، org، date، desc، وvisible، بنفس معنى خانات الخبرات. icon محفوظ من المصدر القديم ولا يغيّر الأيقونة الحالية.

{
  "id": "edu-new-degree",
  "title": "Your Degree",
  "org": "Your University",
  "date": "2026 — 2028",
  "desc": "Your specialization or relevant academic work.",
  "visible": true
}

ترتيب التعليم حسب ترتيب القائمة، وليس حسب تحليل التاريخ. تعديل التعليم في الخط الزمني لا يغيّر تلقائيًا اختصاره في بطاقة Background أو إحصاءات البداية؛ عدّل خانات config الخاصة بالمؤهل لو محتاج توحّدهم.

6. المشاريع — projects

كل كائن مشروع مستقل. تقدر تضيف أو تعدّل أو تخفي أو تعيد ترتيب المشاريع من JSON نفسه؛ مش محتاج تكتب مشروعًا جديدًا داخل portfolio.js.

الخانة مكان ظهورها / معناها
id معرّف فريد بالإنجليزية، مثل new-ai-system. تستخدمه روابط التخصصات داخل capabilities.
title اسم المشروع في البطاقة ونافذة التفاصيل والبحث.
visible false يخفي المشروع ويستبعده من الأعداد والفلاتر والبحث.
category مجال المشروع؛ يُستخدم في الفلاتر والبحث.
type وصف نوع النظام، مثل AI coding assistant. يظهر في التفاصيل وبعض الرسوم.
summary الملخص القصير في البطاقة؛ الأفضل جملة أو جملتان.
desc الوصف التفصيلي داخل نافذة المشروع. استثناء HealthBridge: وصفه من hb.lede.
problem التحدي الهندسي في نافذة التفاصيل.
approach قائمة نصوص لخطوات الحل الهندسي.
stack قائمة نصوص بكل التقنيات المستخدمة في التفاصيل والبحث.
tags قائمة مختصرة بالتقنيات/السمات على البطاقة؛ يُفضّل 3 عناصر. لو حذفت الخانة بالكامل، تُستخدم أول 3 تقنيات من stack.
link رابط مستودع الكود لزر View source code.
demo رابط تجربة حية اختياري؛ "" أو عدم وجوده يخفي زر Launch live app.
art نوع الرسم المفاهيمي المرافق للمشروع، وليس رابط صورة.

القيمة الرسم

مثال مشروع جديد

أضف الكائن التالي داخل قائمة projects، ثم استبدل البيانات التجريبية ببيانات مشروعك:

{
  "id": "my-new-ai-project",
  "title": "My New AI Project",
  "visible": true,
  "category": "Agentic AI",
  "type": "Retrieval-augmented assistant",
  "art": "generic",
  "summary": "A short description of the system and what it solves.",
  "desc": "A more detailed explanation of the project, users, and implementation.",
  "problem": "The real engineering challenge you wanted to solve.",
  "approach": [
    "Explain the first implementation step.",
    "Describe your retrieval or reasoning pipeline.",
    "Explain the deployment and testing approach."
  ],
  "stack": ["Python", "FastAPI", "Docker"],
  "tags": ["Python", "FastAPI", "RAG"],
  "link": "https://github.com/USERNAME/REPOSITORY",
  "demo": ""
}

الترتيب والإخفاء والاختيارات الأولى

  • حرّك كائن المشروع كاملًا لأعلى أو أسفل داخل projects لتغيير ترتيبه.
  • أول 4 مشاريع ظاهرة تدخل العرض المختصر؛ زر Explore all يعرض الباقي.
  • ترقيم SYS_01 وما بعده يُحسب تلقائيًا؛ لا توجد خانة number تحتاج تعديلًا.
  • عداد المشاريع في البداية والأزرار والفلاتر يتحدث تلقائيًا.
  • HealthBridge حالة مخصصة: احتفظ بمعرّفه healthbridge وفي أول القائمة للمحافظة على العرض الرئيسي الحالي. الاسم الظاهر نفسه يمكن تغييره من title، لكن بعض عناوين الرسوم والشروحات الثابتة ستظل تحتاج مراجعة في الكود لو غيّرت هوية المشروع بالكامل.
  • لإخفاء مشروع بدون حذفه: غيّر visible إلى false.
  • لو أضفت مشروعًا وعايزه يظهر أيضًا تحت تخصص معين، أضف معرّفه إلى capabilities[].projectIds.

7. HealthBridge — hb

هذا الجزء يكمل المشروع الذي معرّفه healthbridge داخل projects؛ مش مشروعًا إضافيًا.

النصوص والأرقام

الخانة الاستخدام
lede الوصف التفصيلي في Overview الخاص بـHealthBridge.
featuredSubtitleLines قائمة سطور العنوان الوصفي في البطاقة الرئيسية؛ حاليًا سطران.
featuredDescription وصف البطاقة الرئيسية أسفل العنوان الوصفي.
stats قائمة أرقام المشروع؛ أول 3 عناصر تظهر في البطاقة الرئيسية.
stats[].num قيمة الرقم كنص، مثل "27".
stats[].label الاسم الكامل للمؤشر.
stats[].shortLabel الاسم القصير للبطاقة؛ إذا لم يوجد، يُستخدم label.
flow خطوات الشرح النصية في تبويب Architecture.
flow[].text نص الخطوة.
flow[].icon إيموجي محفوظ من المصدر؛ غير مستخدم في القائمة المرقّمة الحالية.

رسم Architecture نفسه مخطط مخصص داخل src/ProjectArt.jsx. تغيير flow يغيّر قائمة الشرح، لكنه لا يعيد بناء الرسم أو يبدّل أسماء عقده تلقائيًا. لو تغيّرت المعمارية الفعلية أو أرقامها أو أسماء خدماتها، راجع الرسم هناك أيضًا.

الصور — gallery

الخانة داخل كل صورة الاستخدام
localImage مسار الملف المحلي المستخدم فعليًا.
label اسم الصورة في المعرض والنص البديل للصورة.
tag الاسم المختصر أسفل الصورة المصغرة.
img الرابط الأصلي القديم؛ تغيير هذا الرابط وحده لا يستبدل الصورة المحلية.
icon إيموجي قديم غير مستخدم في شكل المعرض الحالي.

ضع الملف الجديد في public/images/، ثم أضف مثلًا:

{
  "localImage": "/images/healthbridge-new-screen.jpg",
  "label": "New Product Screen",
  "tag": "New Screen"
}
  • أضف الصورة داخل قائمة hb.gallery، وليس داخل projects.
  • عدد الصور والتنقل بينها يتحدثان تلقائيًا. احتفظ بصورة واحدة على الأقل.
  • productImageIndex يحدد صورة Product في البطاقة الرئيسية: الفهرس يبدأ من 0؛ القيمة 3 تعني الصورة الرابعة.
  • لو حذفت أو أعدت ترتيب الصور، راجع productImageIndex ليظل يشير إلى صورة موجودة.

الفيديوهات — videos

الخانة الاستخدام
src رابط فيديو YouTube. استخدم الصيغة https://youtu.be/VIDEO_ID بدون معاملات إضافية.
title عنوان الفيديو.
desc وصفه.
poster صورة غلاف اختيارية، مثل /images/demo-poster.jpg.

إذا تركت poster فارغًا، تستخدم الواجهة صورة من المعرض: الصورة الثانية للفيديو الأول، والرابعة للباقي، مع الرجوع للأولى لو غير متاحة. العرض الحالي وشروحه مصممان لجولتين: رحلة المريض ورحلة الطبيب؛ لو غيّرت عدد الفيديوهات، راجع الجملة التعريفية الثابتة في تبويب Demos داخل App.jsx أيضًا.

المفاتيح titlePre، titleHighlight، titlePost، eyebrow، وgithub محفوظة من العرض القديم ولا تتحكم في العناوين أو رابط الكود الحاليين. عدّل اسم المشروع ورابطه داخل projects، لا hb.github.

8. تخصصات Expertise — capabilities

القائمة الحالية فيها 4 تخصصات. كل تخصص يحتوي على:

الخانة معناها
id المعرّف الثابت للتخصص: agents أوvision أوlearning أوproduction. يتحكم أيضًا في اختيار الأيقونة الحالية.
title الاسم الكامل في التبويب واللوحة والبحث.
short الاسم المختصر في أعلى لوحة التخصص.
description الشرح المختصر تحت اسم التبويب.
detail الفقرة التفصيلية في اللوحة.
stages 4 نصوص تمثل مراحل مسار العمل. حافظ على أربع مراحل لتوازن الرسم.
tools قائمة التقنيات المعروضة؛ تدخل أيضًا في البحث.
projectIds قائمة معرّفات مشاريع موجودة داخل projects.
icon قيمة وصفية موجودة في البيانات؛ الكود الحالي يختار الأيقونة باستخدام id، وليس هذه الخانة.

مثال ربط تخصص بمشروع جديد:

"projectIds": ["healthbridge", "codenova", "my-new-ai-project"]

المعرّف لازم يطابق projects[].id حرفيًا. المشاريع المخفية أو غير الموجودة لا تظهر في هذه الروابط. حافظ على معرّفات التخصصات الأربع الحالية؛ إضافة تخصص خامس أو تغيير المعرّفات تحتاج مراجعة الأيقونات والعداد والنصوص الثابتة في App.jsx.

9. قائمة المهارات الكاملة — skills

القائمة تظهر عند فتح THE FULL ENGINEERING STACK.

الخانة معناها
name اسم مجموعة المهارات.
pills نص واحد يحتوي على التقنيات مفصولة بفواصل إنجليزية ,، وليس قائمة JSON.
icon إيموجي محفوظ من المصدر؛ الأيقونة الحالية يحددها ترتيب المجموعة في الواجهة.
visible اختياري؛ يمكنك إضافته بقيمة false لإخفاء المجموعة. 
{
  "name": "Backend & APIs",
  "pills": "FastAPI,Flask,REST APIs,RabbitMQ,Celery",
  "visible": true
}

لإضافة تقنية، أضفها لنص pills مع فاصلة. لتضيف مجموعة، انسخ كائنًا كاملًا داخل skills. عدد المجموعات والتقنيات يتحدث تلقائيًا، والمجموعة الإضافية بعد الأيقونات المخصصة تحصل على أيقونة عامة.

تعديل skills لا يغيّر قائمة capabilities[].tools أو شريط التقنيات الزخرفي في البداية؛ كل واحد له غرض ومكان مختلف.

10. الخريطة التفاعلية — heroModes

القائمة الحالية تحتوي على 3 أوضاع: agents، vision، production.

الخانة الاستخدام
id معرّف الوضع؛ مرتبط بتدرجه اللوني. احتفظ بالقيم الحالية.
label اسم زر الوضع.
nodes 4 عقد، واحدة في كل موضع من الخريطة. حافظ على العدد والترتيب.
nodes[].title عنوان العقدة الصغير، مثل CONTEXT.
nodes[].value النص الرئيسي داخل العقدة، مثل Retrieval + memory.
nodes[].detail الشرح الذي يظهر أسفل الخريطة عند الضغط على العقدة.

تعديل هذه النصوص لا يغيّر الرسم التجريدي الأساسي أو الحركة. لإبدال أصل الرسم نفسه، الملف الحالي هو public/images/neural-core.webp؛ استخدام نفس الاسم يحافظ على المسار. لا تحتاج تغيير التصميم لتعديل الشروحات.

11. الشهادات — certs

الخانة معناها
id معرّف فريد للشهادة. تستخدمه قائمة الاختيارات الأولى.
title اسم الشهادة.
issuer جهة الإصدار، مثل IBM أوNVIDIA. بعض الجهات لها رمز مخصص، والباقي رمز عام.
date السنة فقط كنص، مثل "2026"؛ مهمة لترتيب الشهادات من الأحدث للأقدم.
desc وصف اختياري يظهر في نافذة الشهادة؛ يمكن تركه "".
link رابط التحقق؛ لو "" يظهر زر فتح صورة الشهادة بدل التحقق.
localImage مسار الصورة المحلية المستخدمة فعليًا.
visible false لإخفاء الشهادة بدون حذفها.
img رابط الصورة الأصلي القديم؛ ليس بديلًا عن localImage في الواجهة الحالية.

إضافة شهادة

  1. ضع صورة الشهادة في public/images/.
  2. أضف كائنًا داخل certs:
{
  "id": "cert-new-2026",
  "title": "Your Certificate Title",
  "issuer": "Your Issuer",
  "date": "2026",
  "desc": "What this certification covers.",
  "link": "https://example.com/verify-your-certificate",
  "localImage": "/images/my-new-certificate.jpg",
  "visible": true
}
  1. احفظ. تظهر في القائمة الكاملة، ويتحدث عداد الشهادات تلقائيًا.
  2. لو عايزها في العرض المختصر أيضًا، أضف معرّفها إلى certHighlights.

اختيارات البداية — certHighlights

هذه قائمة معرّفات فقط، وليست كائنات شهادات. ترتيبها هو ترتيب العرض المختصر:

"certHighlights": [
  "cert-new-2026",
  "c3",
  "c1",
  "c5"
]
  • يُفضّل اختيار 4 شهادات للمحافظة على العرض المختصر الحالي.
  • اختر معرّفات موجودة فعلًا في certs.
  • لو أخفيت أو حذفت شهادة، لا يكسر ذلك الصفحة؛ يتم تجاهل معرّفها، لكن حدّث اختياراتك علشان تفضل عندك أربع اختيارات.
  • لو القائمة فارغة أو لا تحتوي على أي معرّف ظاهر، يعرض الموقع أحدث 4 شهادات تلقائيًا.

12. الصور والملفات المحلية

الملف في السورس المسار المكتوب داخل JSON
public/images/my-photo.jpg /images/my-photo.jpg
public/images/new-screen.webp /images/new-screen.webp
public/images/my-certificate.png /images/my-certificate.png
  • لا تكتب public/ داخل قيمة المسار.
  • استخدم أسماء ملفات إنجليزية بسيطة بحروف وأرقام وشرطات، بدون مسافات أو مجلدات فرعية داخل images؛ ده مناسب أيضًا لسكربت تصدير HTML المستقل.
  • تأكد من التطابق في الحروف الكبيرة والصغيرة؛ Photo.jpg يختلف عن photo.jpg على الاستضافة.
  • الصور المحلية تشتغل بدون روابط Google Drive أو خدمات خارجية.
  • صورتك الحالية ملونة فعلًا، وتأثير الأبيض والأسود اتشال. تغيير الصورة لا يحتاج أي تعديل على الألوان أو CSS.

تغيير صورتك الشخصية

  1. ضع الصورة الجديدة مثلًا في public/images/eyad-new-photo.jpg.
  2. غيّر داخل config:
"portrait": "/images/eyad-new-photo.jpg"

استخدم صورة واضحة ومربعة أو قريبة من المربع. مقاس الإطار والقص الحالي يظلان كما هما.

استبدال السيرة الذاتية

ملف السيرة الذاتية الحالي:

public/Eyad-Eldokany-Resume.pdf

يمكنك استبداله بـPDF جديد بنفس الاسم. ملفات PDF مستقلة؛ لا تتحدث تلقائيًا لمجرد تعديل JSON.

لو هتستخدم المولّد المرفق بدل استبدال الملف يدويًا:

pip install reportlab
python3 scripts/create-resume.py

المولّد قالب مختصر يقرأ بعض بيانات المشاريع والمهارات والخبرات والتعليم والشهادات، وفيه نصوص تعريفية واختيارات ثابتة أيضًا. راجع القالب والـPDF الناتج قبل استخدامه، خصوصًا عند حذف مشروع أو شهادة من الاختيارات الأصلية أو تغيير بيانات الهوية. أمر npm run build وحده لا يعيد توليد السيرة الذاتية.

13. القائمة القديمة — fields

fields محفوظة من الموقع الأصلي، لكنها لا تُرسم في التصميم الحالي. خاناتها:

الخانة معناها في البيانات القديمة
id معرّف الحقل.
label عنوانه.
value قيمته.
icon إيموجي.
isLink هل القيمة رابط؟
link الرابط.
visible حالة الظهور في العرض القديم.

إضافة عنصر هنا لا تنشئ بطاقة جديدة في الموقع الحالي. استخدم خانات config الفعلية للمكان والمؤهل والبريد، أو عدّل المكوّن في App.jsx لو أردت إضافة نوع جديد من البطاقات مستقبلًا.

14. ما الذي لا يتغير من JSON؟

علشان تبقى الصورة واضحة، مش كل نص زخرفي أو جزء من شكل الموقع مربوط بـJSON:

المطلوب مكان التعديل
الألوان والخطوط والمسافات والتجاوب src/styles.css — اتركه كما هو لو عايز نفس التصميم.
ترتيب الأقسام وأسماؤها في القائمة وبعض عناوينها الثابتة والأزرار src/App.jsx.
شكل مخطط Architecture وأسماء عقده ونصوصه الثابتة src/ProjectArt.jsx.
بعض التسميات داخل الرسوم المفاهيمية للمشاريع src/ProjectArt.jsx.
شريط التقنيات الثابت أسفل البداية src/App.jsx.
وصف تبويب Demos الثابت وشارات التوفر الثابتة في Contact src/App.jsx.
عنوان تبويب المتصفح ووصف نتائج البحث وOpen Graph وبيانات Person index.html.
الدومين ورابط النشر إعدادات الاستضافة، وليس config.purl.
السيرة الذاتية PDF استبدال الملف أو إعادة توليده ومراجعته.

portfolio.js الآن مسؤول عن تجهيز البيانات، الإخفاء، الفلاتر والأعداد؛ بيانات المشاريع والتخصصات ونصوص الخريطة نفسها موجودة في JSON. التغييرات العادية عليها لا تحتاج تعديل هذا الملف.

15. حفظ نسخة نهائية أو نشر التعديلات

فحص البناء

بعد الانتهاء من التعديل، شغّل:

npm run build

لو نجح، جرّب نسخة الإنتاج محليًا:

npm run preview

افتح الرابط الظاهر وتأكد من الصور والروابط والتفاصيل على الكمبيوتر والموبايل. أخطاء صيغة JSON تظهر أثناء البناء، لكن نجاح البناء وحده لا يؤكد صحة روابطك أو معرّفات المشاريع والشهادات.

إعادة تصدير HTML المستقل

من مجلد السورس:

npm run build
python3 scripts/export-standalone.py ../Eyad-Eldokany-AI-Portfolio.html

سيظهر ملف HTML محدّث بجانب مجلد السورس، وفيه CSS وJavaScript والخطوط والصور والـPDF مدمجين. الإنترنت يظل مطلوبًا فقط للخدمات والروابط الخارجية مثل YouTube وGitHub.

نشر نسخة الموقع

إعدادات البناء:

Framework: Vite
Build command: npm run build
Output directory: dist

لو المشروع متصل بمستودع Git وبنشر تلقائي، ارفع تغييرات JSON والصور معه وانتظر اكتمال النشر. لو بتنشر يدويًا، استخدم ناتج البناء الجديد. تعديل الملفات هنا لا يغيّر موقعك الأصلي المنشور من تلقاء نفسه.

16. أخطاء شائعة وحلولها

المشكلة الحل
الصفحة ظهرت بخطأ بعد الحفظ راجع الفواصل وعلامات التنصيص والأقواس؛ افتح أول خطأ يشير له Terminal أو VS Code.
أضفت مشروعًا ولم يظهر بين الأربعة اضغط Explore all، أو انقل كائنه ضمن أول 4 مشاريع ظاهرة.
مشروع مش ظاهر نهائيًا تأكد إن visible مش false، وإنك بتعدّل src/content.json في السورس الصحيح، مش نسخة احتياطية.
كتبت "false" والعنصر ما اختفاش استخدم false بدون تنصيص.
غيّرت بريدًا أو وصف البداية ولم يتغير استخدم contact-email وheroDescription، وليس email وherodesc القديمين.
صورة مكسورة تحقق من وجود الملف داخل public/images/ ومن تطابق الاسم والمسار /images/... بدون public.
غيّرت img لكن الصورة لم تتغير عدّل localImage أو config.portrait حسب نوع الصورة.
مشروع لا يظهر تحت Expertise أضف معرّفه الصحيح في projectIds للتخصص، وتأكد إنه ظاهر.
شهادة جديدة لا تظهر في الاختيارات الأولى أضف معرّفها إلى certHighlights؛ وجودها في certs يكفي للقائمة الكاملة فقط.
ترتيب الشهادات غريب استخدم سنة فقط في date، مثل "2026".
صورة Product في HealthBridge مكسورة بعد حذف صورة راجع productImageIndex؛ يبدأ العد من 0 ويجب أن يكون أقل من عدد صور المعرض.
المعاينة المحلية اتغيرت لكن HTML القديم لم يتغير أعد البناء ثم شغّل سكربت التصدير؛ HTML لا يقرأ JSON من السورس وقت فتحه.
الموقع المنشور لم يتغير تأكد من رفع التعديلات واكتمال نشر النسخة الجديدة، ثم جرّب تحديثًا قويًا للمتصفح.
اختبارات UI القديمة فشلت بعد إضافة محتوى بعض توقعاتها مثبتة على المحتوى الأصلي: 10 مشاريع و11 شهادة وروابطها. حدّث توقعات الاختبارات مع تغييراتك، ولا تعتبر اختلاف العدد وحده عيبًا في الموقع.
